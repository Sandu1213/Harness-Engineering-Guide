# Detailed Book Outline

## 目录决定

初始提议为 58 章。审查发现其中 11 组主题高度相邻：它们共享核心概念、示例和验证闭环，拆开会重复解释同一前提。本版收敛为 **47 章 + 12 个附录**，不删减知识覆盖。合并理由和后果见 [../.context/DECISIONS.md](../.context/DECISIONS.md)。

## P0 目录审查结论（2026-07-14）

审查确认每章均已包含目标、核心问题、小节、图示、案例、前后关系和交付物。47 章保留不再合并：剩余相邻主题虽有共同术语，但承担不同读者任务，合并会使案例、验收或责任边界不清。

## Part 1：基础思想

### 01. 从 Prompt Engineering 到 Harness Engineering

- **章节目标：** 建立从单次提示词优化到可运行 Agent 系统设计的认知转变。
- **核心问题：** 为什么更好的 Prompt 不能单独解决状态、工具、权限、评估和长期维护问题？
- **主要小节：** Prompt 的作用边界；Harness 的工作定义；输入、过程、结果的可观察性；本书地图。
- **计划图示：** “单次 Prompt”与“模型置于 Harness 中”的边界对比图。
- **计划案例：** 把一个“修复测试失败”的提示改造成具有状态、工具和验收的最小任务循环。
- **与前后章节的关系：** 全书入口；为第 2 章的系统角色和第 4 章的工程原则建立问题意识。
- **预计交付物：** 原创概念图、研究简报、术语表首批条目和最小任务循环伪代码。

### 02. Agent、Harness 与运行环境

- **章节目标：** 区分模型、Agent、Harness 和运行环境的职责与接口。
- **核心问题：** 当结果失败时，如何判断问题在模型能力、编排逻辑、工具接口还是环境约束？
- **主要小节：** 基础模型的能力边界；Agent 的执行循环；Harness 的编排职责；Runtime、Sandbox 与外部系统。
- **计划图示：** 四层责任边界和错误传播路径图。
- **计划案例：** 同一模型在只读仓库与可写测试环境中表现不同的诊断流程。
- **与前后章节的关系：** 承接第 1 章定义；为组件篇的指令、工具、权限与状态建立统一坐标。
- **预计交付物：** 层次图、故障归因表、Attempt Trace 和角色接口清单。

### 03. 仓库即 Agent 上下文

- **章节目标：** 说明为何版本控制的文件系统可成为长期项目记忆和可审查上下文。
- **核心问题：** 如何让新 AI 在不依赖聊天记录的情况下恢复项目目标、状态和约束？
- **主要小节：** 上下文易失性；文件、目录和状态文件的职责；读取顺序；同步与过期风险。
- **计划图示：** 规则、状态、记忆、书稿和校验之间的数据流图。
- **计划案例：** 一个跨会话章节任务通过 `AGENTS.md`、状态表和 handoff 文件恢复执行。
- **与前后章节的关系：** 承接系统边界；为第 6、7、10 章的上下文、记忆和状态管理提供工程落点。
- **预计交付物：** 仓库上下文最小目录模式、交接示例和一致性检查表。

### 04. 构建可靠 Agent 的工程原则

- **章节目标：** 给出适用于不同 Agent 产品的可靠性原则与验收思维。
- **核心问题：** 怎样把“看似完成”变成有证据、可恢复、可审计的完成？
- **主要小节：** 最小可验证闭环；显式状态；最小权限；失败可见；人类责任；渐进复杂度。
- **计划图示：** 从目标、执行、验证、恢复到记录的可靠性闭环。
- **计划案例：** 为自动修改配置的 Agent 设计 dry-run、备份、验证和人工审批。
- **与前后章节的关系：** 汇总 Part 1；作为 Part 2 组件设计和 Part 3 闭环设计的质量基线。
- **预计交付物：** 工程原则清单、Definition of Done 示例和风险矩阵。

## Part 2：Harness 核心组件

### 05. Instructions 与 Prompt

- **章节目标：** 设计可维护的指令层，而非不断累积不可审查的 Prompt。
- **核心问题：** 如何把稳定规则、任务输入、上下文约束和输出格式分层？
- **主要小节：** System、project、task instructions；优先级；冲突处理；结构化输出；指令测试。
- **计划图示：** 指令分层与请求装配顺序图。
- **计划案例：** 将散落的代码审查提示收敛为项目规则、审查模板和任务输入。
- **与前后章节的关系：** 将第 1 章的概念落到最小组件；第 6 章继续解决何种信息应进入上下文。
- **预计交付物：** 指令分层模板、冲突矩阵和检查样例。

### 06. Context Engineering

- **章节目标：** 让读者能够选择、组织、压缩和更新模型可见信息。
- **核心问题：** 在有限上下文窗口内，如何提供足够证据而不注入噪声、过期信息或无关细节？
- **主要小节：** 上下文预算；相关性；来源优先级；检索与摘要；上下文污染；刷新策略。
- **计划图示：** 原始项目资料经筛选、压缩和组装进入执行循环的流程图。
- **计划案例：** 为 Bug 修复任务选择错误日志、调用路径、测试与规则，而不是整个仓库。
- **与前后章节的关系：** 承接指令装配；为第 7 章记忆、第 13 章检索和第 19 章压缩提供方法。
- **预计交付物：** Context Brief 模板、预算表和污染诊断清单。

### 07. Working Memory 与 Long-term Memory

- **章节目标：** 区分短期任务状态与可跨任务复用的记忆，并设计更新规则。
- **核心问题：** 哪些信息应该在当前循环中保留，哪些应该写入可检索、可更正的长期记录？
- **主要小节：** 工作记忆；项目记忆；决策记忆；经验记忆；写入门槛；过期与冲突。
- **计划图示：** 任务状态、总结、决策和知识库之间的读写路径。
- **计划案例：** 一次失败的部署如何成为下一次任务可读取的经验，而不污染项目事实。
- **与前后章节的关系：** 承接上下文选择；为第 16 章反思、第 19 章压缩和第 33 章 Obsidian 案例铺垫。
- **预计交付物：** 记忆分类表、写入决策树和失效记录处理策略。

### 08. Skills 与可复用能力

- **章节目标：** 将重复任务封装为有输入、边界、工具和验收标准的 Skill。
- **核心问题：** 如何避免“万能 Agent”与不可组合的提示词碎片？
- **主要小节：** Skill 的接口；前置条件；权限；输出契约；版本；发现与选择；测试。
- **计划图示：** Skill 注册、选择、执行和验证的生命周期图。
- **计划案例：** 创建一个“审查 Markdown 章节”的 Skill，包含引用、链接与语言检查。
- **与前后章节的关系：** 使用第 5 章指令和第 11 章工具；为第 23、34、37 章的自动化和团队库建立基础。
- **预计交付物：** Skill 模板、接口契约示例和最小 Skill 测试清单。

### 09. Planning 与任务拆解

- **章节目标：** 使计划成为可验证工作分解，而不是模型输出的一段愿望清单。
- **核心问题：** 如何把模糊目标拆成具备输入、依赖、验收和停止条件的子任务？
- **主要小节：** 目标澄清；任务图；依赖；风险；并发边界；计划更新；反计划模式。
- **计划图示：** 从需求到可验收子任务的有向无环图。
- **计划案例：** 将“为 API 增加认证测试”拆为研究、实现、测试、文档与验证任务。
- **与前后章节的关系：** 承接可复用能力；与第 10 章共同形成控制流，并为案例篇提供执行框架。
- **预计交付物：** Plan Brief 模板、任务验收字段和依赖检查规则。

### 10. Workflow 与状态管理

- **章节目标：** 设计可恢复、可观察、可重入的 Agent 工作流。
- **核心问题：** 当长任务中断、重试或交接时，如何知道已经完成什么、应从哪里继续？
- **主要小节：** 状态机；持久化；幂等性；检查点；锁与并发；恢复；状态迁移审查。
- **计划图示：** Research → Outline → Draft → Review → Validate 的章节状态机。
- **计划案例：** 为书籍章节生产过程定义阶段表、阻塞状态和恢复规则。
- **与前后章节的关系：** 承接任务图；为第 18、19、26、27 章的恢复、长任务和协作提供状态基础。
- **预计交付物：** 工作流模板、状态转移表和恢复演练清单。

### 11. Tool Use 与工具协议

- **章节目标：** 把工具调用视为类型化、可观测且有错误语义的接口。
- **核心问题：** 如何让 Agent 知道工具能做什么、何时可调用、结果如何解释、失败如何恢复？
- **主要小节：** 输入模式；输出模式；错误分类；副作用；超时；幂等性；工具结果证据。
- **计划图示：** Agent、工具适配层、外部系统和验证器的调用序列图。
- **计划案例：** 为文件修改工具设计预览、执行、回读验证和错误反馈协议。
- **与前后章节的关系：** 承接 Skill 接口；为 MCP、浏览器自动化和所有案例中的外部操作定义安全边界。
- **预计交付物：** 工具契约模板、错误码分类表和调用审计示例。

### 12. Environment、Sandbox 与权限

- **章节目标：** 让 Agent 的执行能力与权限边界匹配任务风险。
- **核心问题：** 如何避免工具可用即默认可写、可联网、可发布或可读取敏感数据？
- **主要小节：** 运行环境；最小权限；沙箱；凭证；网络；文件系统；确认门；审计。
- **计划图示：** 从只读到高风险外部操作的权限阶梯。
- **计划案例：** 同一部署任务在 dry-run、测试环境和生产环境中的不同授权路径。
- **与前后章节的关系：** 承接工具协议；为第 14、41、42 章的审批、安全与版本回滚建立安全模型。
- **预计交付物：** 权限矩阵、环境清单和高风险操作审批模板。

### 13. Knowledge Base 与检索

- **章节目标：** 设计可归因、可更新的知识检索层，而不是把资料无差别塞进 Prompt。
- **核心问题：** 何时检索、检索什么、如何评估证据质量并把来源带回输出？
- **主要小节：** 知识分层；索引；查询重写；排序；引用回链；新鲜度；检索失败。
- **计划图示：** 问题、检索、证据筛选、上下文装配和引用输出的流水线。
- **计划案例：** 为“当前 API 鉴权方式”检索官方文档并拒绝过期博客结论。
- **与前后章节的关系：** 承接 Context Engineering；为事实核验、案例和 Book Factory 的研究 Agent 提供证据层。
- **预计交付物：** 检索证据卡模板、来源优先级规则和过期检测策略。

### 14. Human-in-the-loop

- **章节目标：** 在自主性、责任、效率与安全之间设计人类参与点。
- **核心问题：** 哪些决定应自动执行，哪些必须要求人类确认、复核或承担最终责任？
- **主要小节：** 审批类型；不确定性阈值；可逆性；升级路径；反馈收集；责任记录。
- **计划图示：** 按影响、不可逆性和证据强度路由的人类审批决策树。
- **计划案例：** Agent 发现依赖漏洞后，自动提出修复建议但将升级与发布交给人类。
- **与前后章节的关系：** 完成核心组件篇；承接权限模型并为反思、审批模式和企业案例提供治理基础。
- **预计交付物：** 审批矩阵、升级模板和责任边界检查表。

## Part 3：智能闭环

### 15. Observation 与状态感知

- **章节目标：** 定义 Agent 应观察哪些状态，以及如何避免只根据最后一段文本作决定。
- **核心问题：** 执行中的成功、失败、漂移、等待和副作用怎样变成可靠的可读信号？
- **主要小节：** 观察模型；日志；事件；快照；外部状态；新鲜度；噪声抑制。
- **计划图示：** 行动、环境事件、状态快照与下一轮决策的反馈回路。
- **计划案例：** UI 测试 Agent 在点击后重取页面状态，而不是根据按钮已点击的假设判断成功。
- **与前后章节的关系：** 承接工作流和工具结果；为评估、重试和浏览器案例提供输入。
- **预计交付物：** 观察点清单、状态快照规范和证据质量等级。

### 16. Reflection 与经验提炼

- **章节目标：** 将轨迹和失败转化为可复用改进，而非生成空泛“复盘”。
- **核心问题：** 怎样区分偶发噪声、可修复缺陷和需要改变 Harness 的系统问题？
- **主要小节：** 轨迹摘要；根因假设；反事实；经验候选准入；验证；过度拟合风险。
- **计划图示：** 执行轨迹经评估、反思、候选改进和再验证回到工作流的闭环。
- **计划案例：** 链接检查连续失败后，判断是网络瞬态、失效链接还是脚本配置问题。
- **与前后章节的关系：** 使用观察和记忆；为自改进边界、Bug 修复案例和经验库设计打底。
- **预计交付物：** Reflection Record 模板、根因/症状区分表和经验准入规则。

### 17. Evaluation 与可验证结果

- **章节目标：** 将“完成”转换为可观察、可复现的成功标准与证据。
- **核心问题：** 不同任务怎样定义正确性、质量、成本和安全，而不以模型自评代替验证？
- **主要小节：** 结果评估；过程评估；单元、集成与端到端验证；评判器；证据保存；误判。
- **计划图示：** 目标、可执行检查、结果证据、判定和反馈的评估管线。
- **计划案例：** 对“更新文档”同时检查 Markdown 格式、链接、事实引用和读者路径。
- **与前后章节的关系：** 承接状态感知；为重试、自改进、测试策略和基准章节定义信号源。
- **预计交付物：** Evaluation Spec 模板、证据矩阵和质量门禁样例。

### 18. Retry、Recovery 与容错

- **章节目标：** 让失败后的重试有条件、有边界并避免放大副作用。
- **核心问题：** 怎样区分可重试错误、需要恢复状态的错误和必须升级给人类的错误？
- **主要小节：** 错误分类；退避；幂等性；补偿操作；检查点；熔断；人工升级。
- **计划图示：** 错误分类到重试、恢复、回滚和升级的状态转换图。
- **计划案例：** 下载资料失败时先重试网络，再切换来源，最后记录阻塞，而不是编造内容。
- **与前后章节的关系：** 使用评估与工作流状态；为长任务、多 Agent 和企业部署提供韧性机制。
- **预计交付物：** 重试策略表、恢复 Runbook 和副作用审查清单。

### 19. Context Compaction 与长任务

- **章节目标：** 在长运行任务中减少上下文膨胀，同时保留可恢复的关键证据。
- **核心问题：** 什么应被压缩、保留、外置或重新检索，才能在成本与可靠性之间平衡？

### 40. 成本、延迟与 Token 管理

- **核心问题：** 如何量化上下文、模型、工具、重试和并发的成本，并在不牺牲关键验证的前提下优化？

### 41. 安全、权限与审计

### 42. Harness 的版本化、回滚和 A/B 测试

## Part 7：Book Factory 与未来

### 43. 用 Harness 写一本技术书

- **章节目标：** 将书籍生产本身建模为有研究、内容、示例、审查和发布门禁的工程系统。
- **核心问题：** 如何让长周期写作保持术语一致、事实新鲜、章节可接力，而不是变成大量孤立 Markdown？

### 44. AI Technical Book Factory：Research、Writing 与 Review Agent

- **主要小节：** 角色契约；输入输出；证据包；审查门；队列；冲突；质量指标；人工最终责任。

### 45. Codex、Claude Code 接力与长期项目上下文
