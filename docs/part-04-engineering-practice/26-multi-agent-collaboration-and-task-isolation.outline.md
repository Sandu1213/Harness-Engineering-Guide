# 第 26 章 Detailed Outline：多 Agent 协作与任务隔离

## 学习目标与中心问题

**学习目标：** 读者能为一组并发候选写出可检查的任务契约和集成门，在路径重叠、共享写入、输入漂移或验证不完整时给出停止或升级理由。

**中心问题：** 多个 Agent 如何合作而不争夺同一份真相、同一个输出或同一次外部效果？

## 小节蓝图

| 小节 | 读者问题 | 内容与边界 | 计划交付 |

| Ownership Claim 与共享工件 | 哪些内容能局部改，哪些必须集中收口？ | 专属输出只有一个当前 owner；共享状态、词表、目录和总校验由集成者持有。 | 所有权矩阵。 |

| 完整案例 | 三位维护者怎样生产三个章节？ | 两位作者写互斥路径，集成者唯一写共享工件；未执行真实 Agent 或 Git 操作。 | 阶段—责任—证据表。 |

## 计划图示

**问题：** 协调者怎样把共享输入分发为专属工作，并在共享写入或冲突出现时将责任收回到集成门？

**图示元素：** 协调者、Task Contract、Agent A/B、输入快照、专属路径、局部验证、Delivery Package、Conflict、Integration Gate、共享工件与 Stop。

**读图结论：** 两个 Agent 可以同时形成局部交付包；共享状态不能由它们直接回写，必须由集成门验证后统一更新。箭头表示本书模型中的工件流，不表示真实进程、文件锁、消息、worktree 或并发执行。

## 计划示例

**模块：** `examples/agent/task-isolation-assessment.mjs`

**输入：** 注入的 Task Contract、Ownership Claim 列表和 Integration Contract。

**输出：** `ready` / `blocked` / `requires_integration` / `not_applicable`，以及路径、路由和原因。

**测试路径：** 合法专属任务；owner 缺失；验收缺失；停止条件缺失；异 owner 路径重叠；同 owner 续接；共享写入路由；集成者缺失；共享路径误称专属；非 Task Contract 输入。

**边界：** 模块不创建 Agent、子进程、worktree、文件锁、消息、浏览器会话、文件、网络或外部副作用。
