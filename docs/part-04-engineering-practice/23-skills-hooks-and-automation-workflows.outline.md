# 第 23 章 Detailed Outline：Skills、Hooks 与自动化工作流

## 章节论证主线

自动化不是单一能力。先按“重复任务、生命周期点、状态编排、事件检查”分配责任，才有可能看清触发、失败、权限、验证与交接分别缺少什么。

## 计划图示说明

- **问题：** 一个请求到来时，如何先选择正确责任而非直接“自动化”？
- **关键节点：** Request、Classify、Skill、Hook、Workflow、Automation、EffectGate、Stop、Observation、Review。
- **关键箭头：** 四类工件只能产生各自记录或报告；授权/批准和观察/验收仍是独立步骤。
- **禁止表达：** 真实 Codex Hook 注册、CI 运行、权限授予、文件写入或结果正确性。

## 计划示例与断言

| 输入场景 | 预期状态 | 证明的教学边界 |
| --- | --- | --- |
| 有任务匹配与输出的只读 Skill | `ready`。 | 任务能力可以有明确入口。 |
| 没有生命周期事件的 Hook | `blocked`。 | Hook 不能缺触发边界。 |
| 用 Hook 承担状态性长流程 | `not_applicable`。 | 应进入 Workflow。 |
| 未批准写入效果的 Hook | `requires_approval`。 | 触发不授予权限。 |
| 没有状态记录或检查点的 Workflow | `blocked`。 | 长程编排要保留恢复接口。 |
| 没有失败策略的 Automation | `blocked`。 | 自动化要让失败可路由。 |
