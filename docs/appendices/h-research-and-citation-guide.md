# 附录 H：Research and Citation Guide

研究的职责是为可验证论证建立证据边界，不是为既定结论寻找装饰性链接。本附录把来源分级、Evidence Card、引用、版权和 Fact Check 组织成可直接复用的工作流。

项目研究政策以 [`.ai/research-policy.md`](../../.ai/research-policy.md) 为准，本附录只是面向读者的操作化版本；研究政策变化应先更新权威文件。章节生产与事实核验接口见[第 43 章](../part-07-future/43-writing-a-technical-book-with-harness.md)和[第 44 章](../part-07-future/44-ai-technical-book-factory-research-writing-and-review-agent.md)。

## H1：先定义研究问题

```markdown
# Research Brief：<主题>

- 读者问题：
- 需要证明的关键陈述：
- 适用产品、版本和时间范围：
- 非范围：
- 优先的一手来源：
- 允许的辅助来源：
- 动态事实刷新期限：
- 版权或隐私限制：
- 仍未知且需要实验的问题：
```

研究开始前检查：

- [ ] 问题可证伪，且能说明什么证据会改变结论。
- [ ] 事实陈述、工程推论、作者建议和待验证假设已分开。
- [ ] 已确定版本、日期、平台或环境边界。
- [ ] 研究范围足以支撑章节，但不以“资料越多越好”为目标。

## H2：来源分级

| 等级 | 来源类型 | 适合支持 | 使用限制 |
| --- | --- | --- | --- |
| A | 官方文档、标准、原始论文、权威仓库与版本记录 | 接口、语义、版本、规范和原始结果 | 仍需确认版本、发布日期和上下文 |
| B | 作者或维护者公开说明、设计说明、维护者确认的问题记录与可复现技术报告 | 设计意图、边界、实际故障和迁移背景 | 不把个人说明外推为正式契约；普通用户问题记录仍按 C/D 级线索处理 |
| C | 高质量二手分析、教程、综述 | 导航、术语解释和背景 | 关键事实回到 A/B 级来源核验 |
| D | 搜索摘要、聚合页、无来源转载、模型生成内容 | 发现检索词或待核验线索 | 不作为关键陈述的最终证据 |

这里的 A–D 是本书用于安排核验动作的路由模型，不是外部通用标准，也不是可信度分数。即使是官方页面，也可能陈旧、只适用于特定版本，或没有直接支持正文的外推。

## H3：Evidence Card

每张卡只服务一个可定位的陈述；同一来源支持多个不同陈述时，分别记录允许结论和禁止外推。

```markdown
# Evidence Card：<证据 ID>

- Claim ID：
- 来源标题与发布者：
- 来源类型/等级：
- URL 或仓库路径：
- 发布日期、版本或提交：
- 访问/核验日期：
- 证据定位：章节、页码、锚点、行号或测试记录
- 来源直接表达：<简短转述；必要时最小引用>
- 允许支持的正文陈述：
- 禁止外推为：
- 动态性与刷新条件：
- 冲突来源：
- 版权、许可或隐私备注：
- 状态：supported / partial / contradicted / unknown / stale
```

Evidence Card 保存定位和受限转述，不复制长段来源。无法回到原文定位的摘要只能作为线索。

## H4：Claim Ledger

写作前建立声明账本，事实核验时逐项关闭。

| Claim ID | 正文位置 | 类型 | Evidence Card | 当前判定 | 必须动作 |
| --- | --- | --- | --- | --- | --- |
| `<ID>` | `<章节与小节>` | `事实 / 推论 / 建议 / 实验结果` | `<证据 ID>` | `supported / narrow / reject / unknown` | `<保留、缩小、删除或补证>` |

以下陈述必须进入账本：

- 产品、模型、工具、协议或标准的能力与限制。
- 数字、比较、性能、成功率、趋势和“最佳”判断。
- 版本、发布日期、默认值、配置项和兼容性。
- 归因给个人、组织、论文或项目的观点。
- 声称已经实际运行、测试、观察或发布的结果。

纯粹的章节导航、明确标记的作者建议和由前文已证事实直接推出的局部说明可以不逐句加引用，但仍要避免伪装成外部共识。

## H5：引用规则

- 引用紧邻其支持的陈述，读者能判断来源对应哪一句或哪一段。
- 优先链接原始页面、具体版本、论文或仓库文件，不链接搜索结果页。
- 一个引用只承担它直接支持的范围；多项主张需要多项证据。
- 转述应保持原意、条件和时态，不把“可能”“实验中”改成确定事实。
- 直接引语只保留必要短句，并提供准确定位；可以转述时优先转述。
- 动态来源记录访问日期和刷新条件；稳定标准记录版本或发布日期。
- 本地运行结果引用命令、输入、环境、退出状态和原始记录，而不是外部资料。
- 章节局部引用键合并到全局参考文献时，由唯一集成者解决重复、重命名和排序。

## H6：版权、许可与数据边界

- [ ] 没有逐句翻译、长段复刻或用多处短摘录重建来源主体。
- [ ] 图、表、截图、代码和数据分别核对许可；网页可访问不等于允许再发布。
- [ ] 改编图表记录原始来源、改编范围和适用许可。
- [ ] 开源许可证、商标规则和署名要求按具体版本核验，不凭项目知名度推断。
- [ ] 私有资料、内部 URL、付费内容、个人数据和保密信息没有进入公开书稿或研究记录。
- [ ] 模型输出仅作为研究辅助或待核验线索，不冒充一手来源。
- [ ] 无法确认许可时，只基于独立核验的事实重新原创表达或自制图示，不复刻受保护的表达结构，并保留待决事项。

版权审查与事实核验是两条独立门槛：内容真实不代表可以复制，获得许可也不代表内容正确。

## H7：动态事实刷新

下列内容在终审前需要重新访问权威来源：

- 当前模型、产品、套餐、价格、限制和默认配置。
- 活跃软件的版本、命令、API、兼容矩阵和弃用状态。
- 法规、政策、标准草案与组织角色。
- 在线排行榜、基准结果、下载量和社区趋势。

刷新记录至少包含旧判定、新判定、核验时间、来源版本和受影响正文。来源失效或内容变化时，不用缓存摘要维持原结论；应缩小、删除或标记未知。

## H8：Fact Check 工作流

1. 冻结待核验正文版本，生成 Claim Ledger。
2. 对每个 Claim ID 打开原始来源或实际运行记录，不依赖研究摘要。
3. 检查主体、谓词、数值、范围、版本、时态和限定词是否都被支持。
4. 判定为 `supported`、`narrow`、`reject` 或 `unknown`。
5. 对 `narrow` 缩小正文，对 `reject` 删除或重写，对 `unknown` 补证或明确未知。
6. 正文变化后重新核对受影响声明、引用和图示。
7. 保存核验记录、未覆盖范围、责任者和最终门槛判定。

```markdown
# Fact Check Record

- 正文文件及版本：
- Claim ID：
- Evidence Card：
- 原始来源复核日期：
- 判定：supported / narrow / reject / unknown
- 核对说明：
- 正文动作：keep / narrow / rewrite / remove / needs_evidence
- 受影响的图示、示例或交叉引用：
- 未核验范围：
- 核验者：
```

## H9：冲突与未知

来源冲突时：

- 先检查是否讨论不同版本、环境、定义或时间窗口。
- 优先保留原始且更接近当前范围的证据，同时呈现实质冲突。
- 不以来源数量投票，也不把搜索排序当可信度。
- 无法解决时缩小正文，明确“当前证据不足”，并记录需要谁做何种验证。

运行结果与文档冲突时，两者都要保留。文档描述契约，运行观察描述特定环境；在没有进一步证据前，不能让任一方静默覆盖另一方。

## H10：交付终检

- [ ] Research Brief、Evidence Card、Claim Ledger 和正文版本可相互追踪。
- [ ] 每项关键陈述由直接、当前且范围匹配的证据支持。
- [ ] 引用链接可访问，且实际内容支持对应陈述。
- [ ] 作者推论和建议没有伪装成来源原话或行业共识。
- [ ] 实验、测试和工具行为均有实际记录；未运行内容没有使用完成时态。
- [ ] 动态事实已在规定窗口内刷新。
- [ ] 版权、许可、隐私和保密门槛分别通过。
- [ ] 冲突、未知、非范围和待批准项仍可见。
- [ ] 全局参考文献由唯一集成者更新，章节作者没有制造并行漂移副本。

事实核验通过只表示当前正文被当前证据支持，不等于内容已获版权批准、工程示例已验证或整本书已批准发布。
