# 附录 J：Claude Code 交接模板

> 本附录把 Claude Code 会话中的局部工作转换为仓库可审查交接。恢复会话、读取 `CLAUDE.md`、使用自动记忆、工作树或子代理，都不能替代当前项目状态、输入快照和新鲜验证。

## 什么时候使用

在以下情形中填写本模板：

- Claude Code 会话被暂停、恢复或转交给另一位执行者；
- 工作从 Claude Code 转给 Codex、人工编辑或其他工具；
- 子代理、并行会话或工作树产生了局部工件，需要主会话或集成者接收；
- 会话记忆与仓库状态不一致，必须保留冲突而不是选择最近叙述；
- 局部审查已经结束，但共享文件、全仓 Validation 或外部动作仍待处理。

模板保存的是可回放证据，不是完整聊天导出。不要复制隐藏指令、密钥、私密会话或与任务无关的自动记忆。

## Claude Code 接手前的读取顺序

本仓库中的 Claude Code 接手者按以下顺序恢复项目：

1. 读取 Claude Code 入口 [CLAUDE.md](../../CLAUDE.md)，只把它当作通往共享规则的适配入口。
2. 按入口读取 [AI_BOOTSTRAP.md](../../AI_BOOTSTRAP.md) 与 [BOOK_RULES.md](../../BOOK_RULES.md)，把它们作为本仓共享项目契约入口，确认共同目标、完成定义和禁止动作。
3. 读取 [PROJECT_CONTEXT.md](../../.context/PROJECT_CONTEXT.md)、[CURRENT_STATE.md](../../.context/CURRENT_STATE.md)、[NEXT_TASK.md](../../.context/NEXT_TASK.md) 与[进度表](../../.ai/progress.md)，比较当前项目事实。
4. 读取相关[决定记录](../../.context/DECISIONS.md)与[当前交接](../../.context/HANDOFF.md)，确认未解决冲突和唯一集成责任。
5. 读取当前任务材料，并记录正文、来源、代码、测试或计划所对应的输入版本。
6. 单独记录会话是新建、继续还是恢复；检查自动记忆、工作树、子代理、工具和权限是否与当前任务相关且仍新鲜。
7. 对当前输入重新执行任务验收。会话恢复不使历史命令结果自动变新。

仓库状态与会话叙述冲突时，不按“更晚的消息”裁决。记录双方主张、证据路径、影响和具名决定责任者，并冻结受影响写入。

## Claude Code 工具差异检查

| 检查项 | 应记录什么 | 不能推出什么 |
| --- | --- | --- |
| 指令入口 | 实际读取的 `CLAUDE.md`、导入链和作用范围 | 上下文入口不等于权限或强制配置 |
| 会话状态 | `new`、`continued`、`resumed` 或 `unknown`，以及对应输入 | 会话恢复不等于项目状态新鲜 |
| 自动记忆 | 是否读取、哪些内容与任务有关、怎样回到仓库证据 | 记忆不等于共享事实源或跨产品同步 |
| 工作树 | 实际路径、分支/输入身份和专属写入面 | 工作树隔离不等于账户、浏览器或数据库隔离 |
| 子代理 | 是否为当前任务使用、上下文来源、局部输出和限制 | 子代理返回摘要不等于集成完成 |
| 工具与权限 | 当前会话已验证的文件、命令、网络和批准边界 | 旧会话或其他工具的能力不能直接继承 |

## 发送交接前的判定

- 会话可恢复但项目输入未重新核对时，状态保持 `draft`。
- 局部工件与有限证据已交付、共享集成仍待执行时，可标记 `delivered`。
- 状态冲突、能力未知、权限缺口或需要人类取舍时，标记 `blocked` 并保留责任入口。
- 新稿、规则或来源使旧审查失效时，把旧包标为 `superseded`，不要让恢复会话继续沿用旧结论。

若目标工具是 Codex，使用[附录 I](i-codex-handoff-template.md)重新填写其工具适配证据。两份模板共享目标、输入、产物、证据、风险和下一任务字段，但从不共享未经核验的产品能力。
