# 附录 A：Prompt Library

本附录提供一组可检索、可裁剪的提示卡（Prompt Card）。它们不是“万能提示词”，也不授予文件、网络、账号或外部系统权限。每张卡只负责一个窄任务，并把输入、输出、边界和验证写在同一处。

权威的项目内版本位于 [`.ai/prompts/`](../../.ai/prompts/)；本附录面向读者解释如何选择和使用这些卡片。下方代码块是可裁剪的读者示例，不是对项目 Prompt 的同步副本。若两处文字不一致，应先核对项目规则、当前任务和链接的项目 Prompt；项目语义变化时先更新权威入口，再刷新本索引。

## 选择方法

使用提示卡前依次回答：

1. 当前要交付的是研究、提纲、正文、审查、示例、图示、事实核验还是交接？
2. 输入路径、版本、来源和验收命令是否明确？
3. 任务是否需要写入、联网、执行命令或影响外部系统？这些能力是否另有授权？
4. 哪个观察可以证明输出正确？哪个未知项必须保留？

任务同时跨越多个阶段时，不要把多张卡拼成一段长 Prompt。先建立工作流，让每张卡只产生下一阶段可审查的输入。

## Prompt Card 契约

| 字段 | 必须回答的问题 |
| --- | --- |
| 适用场景 | 这张卡解决哪个窄问题？ |
| 必需输入 | 缺少什么就应停止？ |
| 输出 | 可交接工件是什么？ |
| 副作用与权限 | 是否只读；写入、联网、执行或外部效果由谁授权？ |
| 禁止外推 | 输出不能证明什么？ |
| 停止条件 | 哪些缺口、冲突或能力未知要求停止？ |
| 验证 | 哪个命令或人工检查支持结论？ |

## A1：Research Brief

- **适用场景：** 为一个已确定范围的章节或技术主题建立研究边界。
- **必需输入：** 读者问题、非范围、动态事实列表、来源优先级、访问日期和目标文件。
- **输出：** Research Brief、待核验项、来源与本书工程扩展的边界。
- **副作用与权限：** 只写目标 Research/References 路径；联网读取和共享引用写入必须另有当前授权。
- **禁止外推：** 搜索结果、摘要或模型记忆不等于最终证据；研究完成不等于正文完成。
- **停止条件：** 读者问题、非范围、目标路径或必需来源不可定位。
- **验证：** 逐条打开一手来源，检查日期、支持范围和引用映射。

```text
为【主题】创建 Research Brief，不写完整正文。
先读取【项目规则和术语】。围绕【读者问题】列出研究范围、非范围、
必须核验的事实、每条事实的一手来源、访问日期、允许陈述、禁止外推、
计划示例与图示，以及 TODO(verify)。动态产品事实必须当日复核。
输出到【目标路径】，不得把搜索摘要或未运行结果写成事实。
```

项目实现见 [Research Brief Prompt](../../.ai/prompts/research.prompt.md)。

## A2：Chapter Outline

- **适用场景：** 将已审查研究材料组织为读者问题驱动的章节蓝图。
- **必需输入：** Research Brief、章节目标、相邻章节边界、术语和目标模板。
- **输出：** 每节问题、证据、示例或图示、连接关系和预期验证。
- **副作用与权限：** 只写 Outline 目标路径；不修改共享术语、引用、目录或进度。
- **禁止外推：** 提纲不能补造研究未支持的事实，也不能代替正文。
- **停止条件：** Research Brief 未审查、章节目标不明或相邻章节责任冲突。
- **验证：** 对照研究简报和相邻章节，检查每节是否有独立学习价值。

```text
根据【Research Brief 路径】为【章节】创建可写作提纲。
按读者问题组织，不按来源段落组织。每节写明要回答的问题、证据、
示例或图示、与前后小节的连接和预期验证；列出不在本章展开的内容。
不得新增无来源事实或重复相邻章节。
```

项目实现见 [Chapter Outline Prompt](../../.ai/prompts/outline.prompt.md)。

## A3：First Draft

- **适用场景：** 使用已核验范围写原创章节或小节。
- **必需输入：** Research Brief、Outline、术语表、引用映射和章节模板。
- **输出：** 以场景、机制、选择、边界和验证推进的原创草稿。
- **副作用与权限：** 只写获准的正文路径；示例、图示、共享状态和外部系统分别授权。
- **禁止外推：** 不逐句翻译来源，不伪造命令、测试、产品能力或用户结果。
- **停止条件：** 输入版本不明、关键事实仍无来源或目标正文路径已被其他 owner 领取。
- **验证：** 检查每项事实的来源、术语首现、示例状态和未验证标记。

```text
依据【Research Brief】和【Outline】起草【章节/小节】。
每段推进一个可观察论点：场景、机制、选择、边界或验证。
首次出现的术语遵循【术语表】，事实只使用已登记来源；
未核验内容保留 TODO(verify)。未实际运行的命令只能写预期结果。
完成后列出技术、图示、示例和事实核验的具体检查点。
```

项目实现见 [Chapter Writing Prompt](../../.ai/prompts/writing.prompt.md)。

## A4：Technical Review

- **适用场景：** 审查技术正确性、范围、接口和证据，不代替作者重写风格。
- **必需输入：** 正文、研究、引用、示例、图示和审查清单。
- **输出：** 按“必须修复／应该修复／建议”分级的可定位发现。
- **副作用与权限：** 默认只写审查记录；正文修复需要任务明确授权并保持最小范围。
- **禁止外推：** “看起来正确”不是审查证据；审查报告也不是修改已完成。
- **停止条件：** 审查目标、输入版本、规则或必需证据缺失。
- **验证：** 每项发现指向位置、理由和最小修复，零发现时说明实际检查范围。

```text
审查【目标文件】，依据【规则/清单】核对技术陈述、边界、接口、
示例、图示和来源。按必须修复、应该修复、建议分类；每项给出位置、
问题、理由和最小修复。不要重写作者风格，不要虚构证据。
若无问题，列出已经实际核查的范围和仍未验证的部分。
```

项目实现见 [Technical Review Prompt](../../.ai/prompts/review.prompt.md)。

## A5：Example Implementation

- **适用场景：** 为一个明确概念建立最小、可执行或明确标注未执行的示例。
- **必需输入：** 读者问题、输入输出、环境、失败边界、成功条件和验证命令。
- **输出：** 最小示例、测试、运行说明和限制。
- **副作用与权限：** 只写获准示例路径；命令、网络和外部系统动作按环境单独授权。
- **禁止外推：** 纯内存测试不能证明真实 API、浏览器、权限或业务效果。
- **停止条件：** 接口、环境、验收或外部效果边界无法判定。
- **验证：** 涉及行为代码或缺陷时先观察预期失败，再运行专用测试、演示和受影响的总校验；文档、配置或只读样例使用对应检查并说明为何不需要 RED。

```text
为【概念】创建最小示例。先写读者问题、环境前提、输入、输出、
成功条件、失败边界和安全限制。优先标准库与已有依赖。
提供【测试命令】和【演示命令】；只有实际运行后才记录实际结果。
明确示例没有执行或证明的外部动作。
```

项目实现见 [Example Prompt](../../.ai/prompts/example.prompt.md)。

## A6：Diagram Review

- **适用场景：** 用 Mermaid 回答一个结构、状态或证据关系问题。
- **必需输入：** 图要回答的问题、节点边界、箭头语义、正文术语和目标路径。
- **输出：** Mermaid 源、文本替代说明、正文位置和渲染证据。
- **副作用与权限：** 只写获准图源、导出和正文位置；渲染器执行需要当前环境允许。
- **禁止外推：** 可渲染不等于语义正确；图中的箭头不代表真实动作已发生。
- **停止条件：** 单一问题、节点责任、箭头语义或术语事实源不明确。
- **验证：** 比较正文代码块与图源，实际渲染并检查裁切、文字和箭头。

```text
为【章节】设计一张回答【单一问题】的 Mermaid 图。
先定义边界、节点、箭头语义和读图结论，再输出到【目标路径】。
术语必须与正文一致；提供文本替代说明。实际渲染后记录命令和尺寸，
未渲染时明确标注，不得声称图已验证。
```

项目实现见 [Diagram Prompt](../../.ai/prompts/diagram.prompt.md)。

## A7：Fact Check

- **适用场景：** 逐项核查产品能力、API、版本、数字、作者观点和运行结论。
- **必需输入：** 原陈述、正式来源、访问日期、引用映射和运行证据。
- **输出：** 已验证、需改写或待核验的逐项裁决。
- **副作用与权限：** 默认读取来源并写事实核验记录；重跑命令和修改正文需要各自授权。
- **禁止外推：** 来源只支持部分结论时不能保留更宽陈述；找不到证据不等于结论为真。
- **停止条件：** 原陈述无法定位、正式来源不可识别或当前能力不能取得必需证据。
- **验证：** 重新访问一手来源，并独立重跑书中声称已运行的命令。

```text
对【目标】逐项核查可归因陈述。为每项记录原陈述、来源、访问日期、
来源直接支持的范围、结论（已验证/需改写/待核验）和禁止外推。
优先官方资料、原始论文或原始仓库。证据不足时缩小、标记或删除，
不要用搜索摘要或记忆补全未知事实。
```

项目实现见 [Fact Check Prompt](../../.ai/prompts/fact-check.prompt.md)。

## A8：Handoff

- **适用场景：** 把一个可验收任务编译为下一位执行者可读取的项目状态。
- **必需输入：** 目标、修改文件、实际命令与结果、未验证范围、风险和唯一下一步。
- **输出：** 可追溯交接记录。
- **副作用与权限：** 只更新获准交接路径；状态、引用、目录和发布工件由其具名责任者处理。
- **禁止外推：** 不写思维链、密钥、猜测或没有执行过的命令。
- **停止条件：** 无法确认输入版本、真实修改、验证结果或下一责任者。
- **验证：** 下一位只读取仓库工件也能定位输入、证据和停止条件。

```text
为【任务】生成交接记录。只写可验证事实：目标、已完成交付物、
修改文件及职责、实际命令/退出状态/关键结果、未验证范围、风险、
共享状态是否同步，以及下一位应先读的文件和唯一下一步。
不要写聊天推理、密钥或未经证实的猜测。
```

项目实现见 [Handoff Prompt](../../.ai/prompts/handoff.prompt.md)。

## 组合规则

- Prompt Card 可以被 Skill 引用，但 Prompt 本身不负责发现、版本和权限。
- 多张卡的顺序、重试与交接属于 Workflow，不应隐藏在一段长提示中。
- 事实核验应读取原始来源和运行证据，不能只审查正文措辞。
- 修改、发布、发送、部署等副作用必须由任务契约和运行环境单独授权。
