# 附录 I：Codex 交接模板

> 本附录把一次 Codex 局部工作的目标、输入、产物、证据、风险和下一任务编译成可审查交接。模板不会授予权限、恢复会话、运行命令或把局部结果写成项目完成。

## 什么时候使用

在以下任一情形中使用本模板：

- Codex 会话即将结束，但任务还要由另一会话、工具或人继续；
- Codex 子代理返回了局部结果，需要主线程核对和集成；
- 当前工作只修改专属路径，共享状态要交给唯一集成者更新；
- 输入、权限、工具或验证范围发生变化，需要明确停止位置；
- 局部检查已经通过，但全仓 Validation、外部效果或发布仍未执行。

交接包的 `delivered` 只表示“局部证据已交付”。它不等于集成门已经接受，也不等于下一位执行者可以开始修改。

## Codex 接手前的读取顺序

本仓库中的 Codex 接手者应先建立输入基线，再读取任务材料：

1. 读取 Codex 入口 [AGENTS.md](../../AGENTS.md)，确认适用于当前路径的规则。
2. 读取 [AI_BOOTSTRAP.md](../../AI_BOOTSTRAP.md) 与 [BOOK_RULES.md](../../BOOK_RULES.md)，把它们作为本仓共享项目契约入口，确认工作流、完成定义和禁止动作。
3. 读取 [PROJECT_CONTEXT.md](../../.context/PROJECT_CONTEXT.md)、[CURRENT_STATE.md](../../.context/CURRENT_STATE.md)、[NEXT_TASK.md](../../.context/NEXT_TASK.md) 与[进度表](../../.ai/progress.md)，比较目标、状态和下一任务。
4. 读取相关[决定记录](../../.context/DECISIONS.md)与[当前交接](../../.context/HANDOFF.md)，定位仍有效的决定、风险和共享写入责任。
5. 只读取当前任务需要的章节、代码、来源、模板和审查记录，并记录输入版本或内容摘要。
6. 检查当前会话实际可见的工具、沙箱、批准、网络和子代理能力；未知能力保持 `unknown`。
7. 对当前输入重新运行验收检查。历史输出只能证明当时、当文件范围内的结果。

若入口缺失、状态互相冲突、输入已漂移、专属路径重叠或任务依赖未授权能力，应停止写入并把问题写进交接，而不是自行补全项目状态。

## Codex 工具差异检查

填写交接前，单独核对本次 Codex 环境。不要从另一工具或旧会话复制能力声明。

| 检查项 | 应记录什么 | 不能推出什么 |
| --- | --- | --- |
| 指令入口 | 实际读取的 `AGENTS.md` 路径及适用范围 | 文件存在不表示规则已被正确执行 |
| 运行表面 | CLI、IDE、API 或其他实际入口；无法确认则写 `unknown` | 名称相同不表示版本、工具或权限相同 |
| 文件与沙箱 | 已验证的可读、可写路径和禁止路径 | 能读取不等于获准修改 |
| 命令与网络 | 当前任务实际允许且已验证的能力 | 工具可见不等于命令已运行或网络已授权 |
| 子代理 | 是否可用、如何隔离、返回了什么局部证据 | 子代理完成不等于文件隔离或结果已集成 |
| 外部状态 | 浏览器、账户、数据库、缓存和凭证是否独立核验 | 同一仓库不等于外部状态相同 |

## 可复制模板

复制下面内容到任务专属交接文件，再替换所有尖括号占位符。保留不适用字段并填写 `not_applicable`，不要直接删除证据槽位。需要刷新本仓当前交接时，由唯一集成者按 [handoff prompt](../../.ai/prompts/handoff.prompt.md) 把已核验内容更新到 [`.context/HANDOFF.md`](../../.context/HANDOFF.md)；局部责任者不得用任务文件直接覆盖共享交接。

## 发送交接前的判定

- 缺少输入快照、实际命令结果或未运行范围时，状态保持 `draft`。
- 局部工件和有限证据已经齐全，但仍待集成时，可标记 `delivered`。
- 权限、冲突、输入漂移或决定缺口阻止交付时，标记 `blocked` 并写明责任者。
- 新输入使旧交接失效时，旧包标记 `superseded`，不要覆盖历史证据。

接收者仍须重新执行读取顺序和新鲜检查。若目标工具是 Claude Code，使用[附录 J](j-claude-code-handoff-template.md)填写其独立适配证据；术语边界见[附录 K](k-glossary.md)。
