# 第 18 章 Technical Review

## 审查范围

- 第 18 章 Research Brief、候选资料、Outline、正文、Example Plan 与 Fact Check。
- `retry-recovery-assessment` 的纯内存契约及其测试矩阵。
- 第 15、17、19、20 章的职责边界。

## 审查结论

本章以原创的 `Recovery Contract` 组织重试、观察、恢复、补偿、停止与升级。来源事实只用于 HTTP 幂等重试的受限语境、Google SRE 的重试放大风险和 Azure 补偿事务的应用特定边界；没有把其中任一来源变成跨产品默认实现。

## 发现与修正

发现一项应修复的契约次序问题：原判断器在失败证据未知时先返回 `needs_observation`，可能让不受支持的 `effectStatus` 绕过契约校验。现已将效果状态枚举校验前置，并加入 `not_a_status` 测试，预期为 `needs_spec` / `effect_status_not_supported`。修复后专用测试实际通过。

## 已复核的边界

- 第 15 章产生关联状态快照；本章消费效果状态，不假装采集真实外部状态。
- 第 17 章判断证据是否接受；本章把其拒绝、补证或复核信号转换为受限的下一步候选，不改变验收结论。
- 第 19 章讨论长任务压缩；本章只规定检查点应为恢复保留什么信息。
- 第 20 章讨论自改进边界；本章没有允许 Agent 修改自己的重试策略、权限或补偿规则。

## 来源复核

- CH18-REF-01：RFC 9110 第 9.2.2 节，只支持 HTTP 幂等方法和受限自动重试语境。
- CH18-REF-02：Google SRE 的重试放大、随机化指数退避、上限、预算、多层重试与分类建议；无固定参数外推。
- CH18-REF-03：Microsoft 补偿事务模式的进度、幂等、关联、审计、人工和不可逆边界；无回滚保证外推。
